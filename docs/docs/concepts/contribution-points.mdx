# Reactor contribution points

Every service the SDK lets a host replace is a [Datalayer
Reactor](https://reactor.datalayer.tech) contribution point. Python and
TypeScript define the same points, with the same ids and contracts (members
spelled `snake_case` in Python, `camelCase` in TypeScript), listed in
[`protocol/reactor-points.json`](https://github.com/datalayer/personal-agent-protocol/blob/main/protocol/reactor-points.json).
Each SDK's tests hold it to that file, so a point added to one SDK and not the
other fails CI.

## Resolution

- A lower `order` wins. The SDK's own defaults contribute at `order` 100, so
  any host contribution with a lower order replaces them.
- Two contributions at the winning order are ambiguous and fail closed: the
  SDK refuses rather than pick one by load order.
- A point with no default and no contribution fails closed when the SDK needs
  it (`no active … contribution`). `pap.company.api` and `pap.company.mcp` are
  optional: with none, the company publishes no API or MCP server.
- `pap.company.operationExecutor` resolves per action: the lowest-order
  executor whose `action` names the operation's performs it; two at that order
  leave the operation `in_progress` instead of performing it twice.
- Contributions follow their plugin: disabling or unregistering a plugin
  removes what it contributed, and the SDK reads each point when it needs it,
  never caching a provider.

approved URL within its `MetadataFetch` bounds and connects only to the
addresses the URL safety policy approved; TypeScript's is a `fetch`, each URL
approved by the policy first.

## Tenants

Two contracts are tenant-scoped: `pap.pairwiseUserIdStore` receives the
`tenant_id` (`tenantId`) with each request, and `pap.dpopProofProvider`
receives it in each `DpopProofRequest`. The SDK always passes the tenant of
the call it is making, so a host keeps one tenant's pairwise IDs and proof
keys apart from another's; the tests check that one tenant's ID is never
returned for another and that each proof is asked for the request's own
tenant. A company is one tenant of its own points: a host serving several
companies builds one company (and one Reactor) for each.
