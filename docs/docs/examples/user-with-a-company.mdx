# A user with a company

<Deck spec={deck} />

The cases [A Person and a Company](/examples/cases/pap-a-person-and-a-company) and
[A Change, Approved Once](/examples/cases/pap-approve-once) tell this story in a
reader's words; this page is both, on the wire.

The whole journey of the upstream home page's example: Ada's jacket is not
warm enough, and she asks her personal agent, Atlas, to exchange it at
Manzanita Outfitters. Both sides come from this SDK. Manzanita is the
[reference company](/guides/company/) assembled from Reactor contributions,
Atlas is a personal agent with a real ES256 identity, and they talk real HTTP
over ASGI in one process, with no network and no model in the protocol path.

```mermaid
sequenceDiagram
  autonumber
  actor Ada
  participant Atlas as Atlas (personal agent)
  participant M as Manzanita (company)
  Atlas->>M: Discovery + OAuth metadata
  Atlas->>Atlas: Start a Session: a random sid, signed out, no network call
  Ada->>Atlas: Where is my jacket order?
  Atlas->>M: Start conversation + Poppy-Session, no access token
  M-->>Atlas: Sign in first + authorization: insufficient_scope
  Atlas->>M: Device authorization for the scopes it needs
  Atlas->>Ada: Open manzanita.example/device and enter the code
  Ada->>M: Signs in and approves on Manzanita's page
  Atlas->>M: Poll → access token + refresh token
  Ada->>Atlas: Exchange it for something warmer
  Atlas->>M: Same conversation, same Session, with the access token
  M-->>Atlas: An operation: USD 70.00 more
  Atlas->>Ada: Show summary and terms
  Ada->>Atlas: Approve this revision
  Atlas->>M: The same request, with the approval
  M-->>Atlas: Exchanged ..., in Manzanita's words
  Atlas->>M: The same approval again (a retry)
  M-->>Atlas: The original response, performed once
  Atlas->>M: Refresh narrowed to orders:read
  Ada->>Atlas: Sign me out
  Atlas->>M: Revoke the refresh token, the Session goes on signed out
```

Each step is one feature, documented on its own page:
[company discovery](./company-discovery), [session lifecycle](./session-lifecycle),
[conversation control](./conversation-control) for the `authorization`
event, [Device Sign-In](./device-sign-in), [Operations](./operations), and
[Refresh tokens](./account-tokens).

The model sees the steps in plain words: what the company asked, where Ada
signed in, what was proposed, what she approved, and what Manzanita did, in
its own words. It never sees the device code, a token, a delegation, or a
Session JWT. Ada approves in the host's interface; the model can explain the
proposal but cannot approve it.

The same world runs in `personal_agent_protocol/__tests__/test_company_end_to_end.py`,
which also covers Mediated Sign-In with a one-time code, streaming, and a
stranger refused with `conversation_not_found`.
