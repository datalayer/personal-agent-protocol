# Direct Sign-In

Both SDKs implement safe Direct Sign-In primitives: random OAuth state, RFC
7636 S256 PKCE, authorization URL construction, callback state and issuer
validation, and a redacted authorization-code exchange grant. Both also
implement the complete personal-agent orchestration through
`DirectSignInClient`.

:::caution Host services remain mandatory

The orchestrator resolves `pap.authorizationStateStore`, `pap.browserHandoff`,
`pap.signer`, and `pap.dpopProofProvider` from Reactor. The core installs no
in-memory fallback. The state store must provide atomic `take`; the browser
handoff must open the URL only for the user; signing and DPoP providers must
keep private keys in protected custody.

:::

## Python

```python
import httpx

from personal_agent_protocol import (
    DirectSignInClient,
)

async with httpx.AsyncClient() as http:
    sign_in = DirectSignInClient(reactor=reactor, http_client=http)
    started = await sign_in.begin(
        authorization_endpoint="https://auth.example.com/oauth/authorize",
        token_endpoint="https://auth.example.com/oauth/token",
        issuer="https://auth.example.com",
        client_id="https://agent.example/agent.json",
        redirect_uri="https://agent.example/oauth/callback",
        scopes=("poppy:read",),
        tenant_id="application-42",
        pairwise_user_id=pairwise_user_id,
        session_id=signed_out_session.session_id,
    )

    # Later, at the registered callback route. Never pass this URL to a model.
    result = await sign_in.complete(incoming_callback_url)
    print(result.granted_scopes, result.missing_scopes)
```

`begin()` stores the redacted pending request under a SHA-256 reference to its
state and then invokes the trusted browser handoff. `complete()` atomically
consumes that state before validating the exact redirect and issuer, so a
callback cannot be replayed. Expired, unknown, and already-used states produce
the same safe error class.

The exchange signs a fresh client assertion and creates a fresh DPoP proof for
every attempt. It follows no redirects and retries one `use_dpop_nonce`
challenge. A successful response must be a signed-in DPoP token for the
existing Session. Extra scopes are rejected; omitted scopes are returned in
`missing_scopes` so the application can continue with reduced authority or ask
the user what to do. If the response includes an Account Token, the callback
controller must immediately move it into protected token storage and expose
only an opaque reference beyond that boundary. Account Token rotation,
narrowing, exchange, and revocation remain a separate implementation milestone.
Denial consumes state and exposes no remote description; recovery starts a new
flow.

## TypeScript

```typescript
import {
  DirectSignInClient,
} from '@datalayer/personal-agent-protocol';

const signIn = new DirectSignInClient({ reactor, fetch });
const started = await signIn.begin({
  authorizationEndpoint: 'https://auth.example.com/oauth/authorize',
  tokenEndpoint: 'https://auth.example.com/oauth/token',
  issuer: 'https://auth.example.com',
  clientId: 'https://agent.example/agent.json',
  redirectUri: 'https://agent.example/oauth/callback',
  scopes: ['poppy:read'],
  tenantId: 'application-42',
  pairwiseUserId,
  sessionId: signedOutSession.sessionId,
});

// Later, at the registered callback route. Never put this URL in UI/model state.
const result = await signIn.complete({
  callbackUrl: incomingCallbackUrl,
  signal: request.signal,
});
console.log(started.expiresAt, result.grantedScopes, result.missingScopes);
```

The TypeScript flow has the same one-use, redirect, issuer, nonce, Session, and
scope guarantees as Python and propagates an optional `AbortSignal` to both
exchange attempts. Use it in a trusted backend or desktop host whose Reactor
contributions keep assertion signing and authorization state out of browser
code. A web Preview should request the flow through that host and receive only
safe status.

The request URL, state, verifier, authorization code, client assertion, DPoP
proof, Session Token, and Account Token are redacted by default. Reveal them
only at the browser handoff or final HTTPS serialization boundary. They must
not enter model context, logs, analytics, A2UI state, or callback error text.

See upstream [Direct Sign-In](https://personalagentprotocol.org/docs/spec#45-direct-sign-in)
for the complete normative flow.
