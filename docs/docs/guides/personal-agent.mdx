# Build a personal agent

This guide separates the working SDK surface from the remaining roadmap.

## Available now: discover and validate a company

1. Accept a company domain—not an arbitrary metadata URL—from the task.
2. Call the discovery client.
3. Choose only an interface and extension your runtime supports.
4. Keep the returned issuer and endpoints attached to that verified company.

```python
from personal_agent_protocol import DiscoveryClient

async with DiscoveryClient() as client:
    company = await client.discover("example.com")
    print(company.document.organization.name)
    print(company.oauth_metadata.token_endpoint)
```

Do not send credentials during discovery. Python rejects private, loopback,
link-local, and otherwise non-public resolved addresses by default. Server-side
TypeScript callers should contribute a DNS-aware URL safety policy.

## Available now: start or renew a signed-out session

Generate a pairwise identifier once for each internal user and company issuer,
then store the mapping. The helper creates a suitable random value; persistence
is the application's responsibility.

```python
from personal_agent_protocol import (
    build_session_assertion_claims,
    generate_pairwise_user_id,
)

user_id = generate_pairwise_user_id()
claims = build_session_assertion_claims(
    client_id="https://agent.example/agent.json",
    pairwise_user_id=user_id,
    token_endpoint="https://auth.example.com/oauth/token",
)
```

The lower-level result is unsigned. `SessionClient` uses Reactor signer and
DPoP-proof contributions to create fresh proofs and send the real token
request. Those host services must keep private keys outside model context and
tool arguments. See [Signed-out sessions](/guides/sessions/) for the complete
implemented boundary.

## Lifecycle status

The high-level client now implements the first step. The remaining lifecycle
is planned:

1. **Implemented:** start or renew a signed-out session;
2. **Planned:** choose direct, device, or mediated sign-in;
3. **Planned:** obtain the smallest scopes and resource needed for the task;
4. **Planned:** call an API, browse, or open a conversation;
5. **Planned:** confirm exact operation revisions for consequential actions;
6. **Planned:** discard session credentials and revoke account access when
   requested.

Do not treat the remaining value objects as production PAP support. Track
readiness on [Protocol status](/protocol/status/).
