# Use PAP from Pydantic AI

The PAP repository's
[`examples/pydantic-ai`](https://github.com/datalayer/personal-agent-protocol/tree/main/examples/pydantic-ai)
directory contains deliberately small agents. Each exposes one PAP
feature as a Pydantic AI tool; the
[README](https://github.com/datalayer/personal-agent-protocol/tree/main/examples/pydantic-ai#readme)
lists every one. Among them:

| Example                                                         | PAP feature                                                  | Tool result                              |
| --------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------- |
| [Company discovery](/examples/company-discovery/)               | HTTPS discovery, version/domain/issuer validation            | Public company capability summary        |
| [Agent identity](/examples/agent-identity/)                     | Client metadata and same-domain JWKS                         | Client identity and signing policy       |
| [Delegation](/examples/delegation/)                             | A delegation's claims, naming no User and no Company         | Claim names; identifiers withheld        |
| [Direct Sign-In boundary](/examples/direct-sign-in-boundary/)   | Random state, S256 PKCE and browser handoff                  | Scopes and security properties only      |
| [Direct Sign-In lifecycle](/examples/direct-sign-in-lifecycle/) | Callback, exchange, partial consent, refresh token custody   | Lifecycle evidence; all secrets withheld |
| [Session JWT](/examples/session-jwt/)                           | Method, URL, token, company and replay binding               | Verification policy; secrets withheld    |
| [Session transport](/examples/session-transport/)               | `invalid_session` restart, refused redirects, protected headers | Transport policy; secrets withheld    |
| [Session lifecycle](/examples/session-lifecycle/)               | Start, a Session JWT per request, and restart over HTTP      | Lifecycle evidence; secrets withheld     |
| [Browser Session](/examples/browser-session/)                   | One-time code, Session header, form POST, replay rejection   | Browser policy; secrets withheld         |
| [Company APIs](https://github.com/datalayer/personal-agent-protocol/tree/main/examples/pydantic-ai/company-apis) | OpenAPI with a Bearer token and the Session header, MCP with a Bearer for its URL alone | Orders, statuses, and summaries |
| [Company service](https://github.com/datalayer/personal-agent-protocol/tree/main/examples/pydantic-ai/company-service) | A company built with the SDK, used end to end | Steps and how often it performed |
| [Sign-in display](https://github.com/datalayer/personal-agent-protocol/tree/main/examples/pydantic-ai/sign-in-display) | `PapSignIn`: the page's whole display vs `model_view()` | Model view; the page's shape only |

Install the example dependency and run one agent:

```bash
python -m pip install -e '.[examples]'
export OPENAI_API_KEY=...
python examples/pydantic-ai/company-discovery/app.py
```

The default model is `openai:gpt-4o-mini`. Set `PAP_EXAMPLE_MODEL` to any
Pydantic AI model string supported by your installed provider.

Validate all agent definitions without making a model request:

```bash
python scripts/validate_pydantic_ai_examples.py
```

The company and identity tools may return only verified public summaries. The
Session, Direct Sign-In, and Session JWT tools create real cryptographic material
internally but return policy status only. Pairwise subjects, `jti`, assertions,
authorization URLs, OAuth state, PKCE verifiers, Session JWTs, key material,
and tokens never enter the prompt, tool result, or transcript.

Use `direct-sign-in-boundary` when learning how an authorization request is
constructed. Use `direct-sign-in-lifecycle` when integrating the complete
asynchronous flow: it installs Reactor contributions for one-use state,
trusted browser handoff, and signing; signs in an existing Session; and
proves that replayed callback state is rejected. The callback is synthesized
inside host code because callback URLs and authorization codes are never valid
model inputs.
