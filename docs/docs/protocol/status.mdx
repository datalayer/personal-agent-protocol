The package version and protocol version are independent. A future SDK release
can support more than one protocol profile.

## Known gaps

- Python preflight validates resolved addresses, but transport-level address
  pinning is still needed to fully close the DNS-rebinding interval.
- Python and Node now reject non-public DNS results before metadata requests,
  but their default transports do not yet pin the connection to an approved
  resolved address. Production deployments need a pinning transport or an
  enforcing egress proxy to fully close the DNS-rebinding interval.
- Pairwise ID generation and a file-backed atomic Python reference store are
  implemented. Distributed deployments must contribute their own transactional
  `pap.pairwiseUserIdStore` and own retention and erasure policy.
- Python and TypeScript Direct Sign-In perform trusted browser handoff, atomic one-use
  state consumption, exact callback validation, fresh assertion/DPoP exchange,
  one nonce retry, and partial-scope reporting. Hosts still provide the
  authorization-state store, browser surface, signer, and DPoP key custody.
- Session clients sign fresh claims, create a DPoP proof, and send the token
  request. Local JOSE implementations are available, but applications still
  own key selection and custody.
- Security contribution contracts exist, but the SDK deliberately ships no
  default protected key store, durable replay cache, token store, general
  cache, or browser handoff.
- Models for conversations and Operations are aligned and fixture-tested, but
  do not yet imply working clients or server handlers.
- The CLI does not expose auth, session, conversation, Operations, or
  conformance workflows until their service and protected-store boundaries are
  implemented.

The machine-readable requirement ledger lives in
[`protocol/requirements.yaml`](https://github.com/datalayer/personal-agent-protocol/blob/main/protocol/requirements.yaml).

PAP itself still leaves payments, push notifications, and message attachments
as open topics. See [Open topics and SDK gaps](./open-topics) before designing
private extensions or interpreting an unimplemented SDK service as an omission
from the protocol.
