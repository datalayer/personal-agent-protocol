# Compatibility

This page is versioned with the SDK: it describes **SDK 0.37.4**.

## The PAP version implemented

| | Python (`personal_agent_protocol`) | TypeScript (`@datalayer/personal-agent-protocol`) |
| --- | --- | --- |
| PAP profile | `PROTOCOL_PROFILE` = `0.4` | `PROTOCOL_PROFILE` = `"0.4"` |
| Specification revision | `PROTOCOL_REVISION` = `2026-11-10` | `PROTOCOL_REVISION` = `"2026-11-10"` |
| Operations extension | `OPERATIONS_VERSION` = `3` | `OPERATIONS_VERSION` = `"3"` |
| Version 1.0, the default | `DRAFT_PROTOCOL_VERSION` = `1.0` (`DRAFT_PROTOCOL_REVISION` = `2026-11-14`, 1.0 as published) | `DRAFT_PROTOCOL_VERSION` = `"1.0"` (`DRAFT_PROTOCOL_REVISION` = `"2026-11-14"`) |
| Default version | `DEFAULT_PROTOCOL_VERSION` = `1.0` | `DEFAULT_PROTOCOL_VERSION` = `"1.0"` |

Both SDKs implement [PAP version 0.4](https://personalagentprotocol.org/docs/0.4/spec)
as published on **2026-11-10** (upstream commit `4803900`, the 1.0 release candidate, frozen at `/docs/0.4/spec`), the **Operations
extension version 3**, the **Mediated Sign-In extension version 1** and the **Browser Control extension version 1**, and
[version 1.0](https://personalagentprotocol.org/docs/1.0/spec) as published on **2026-11-14** (upstream commit `8c02b42`,
frozen at `/docs/1.0/spec`) since 0.37.0. Since 0.36.0 1.0 is the default: both SDKs and both reference companies announce
and accept `protocol_version` `1.0` only unless told otherwise; where 1.0 changes 0.4's rules, the SDK applies them at 1.0
only. 0.4 stays available to a personal agent (`protocol_versions` on the discovery client) and a company
(`CompanyConfig.protocol_versions`) that name it. With both versions, the newest one both sides serve is chosen (spec 3.4). Operations version 2 is
not supported on either side. Operations on websites (the `Poppy-Operation` header and the extension's `endpoint`) are implemented
since 0.34.0, with the Browser Control extension. A test holds the two SDKs, this page, the package
descriptions, `protocol/UPSTREAM.md`, and the requirement ledger
(`protocol/requirements.yaml`) to the same three values. A published version
does not change; a later upstream version is reviewed and released as a new
profile, never picked up from an unattended fetch.

The Python package `personal-agent-protocol` and the npm package
`@datalayer/personal-agent-protocol` are released together, from one tag, at
the same version. The SDKs stay `0.x` while PAP is a draft; any minor release
may break the API, and the [migration guide](/releases/migration/) says how.
Python 3.10 to 3.13 and Node.js 22 are tested.

## The four pairings

A personal agent and a company built with this SDK interoperate in all four
language pairings:

| Personal agent | Company |
| --- | --- |
| Python | Python |
| Python | TypeScript |
| TypeScript | Python |
| TypeScript | TypeScript |

Each pairing runs the whole conformance suite over real TCP and TLS before a
release, and the [conformance report](/protocol/conformance-report/) lists
every case's outcome; a case a side cannot run is skipped, never passed, with
its reason. Use the same SDK version on both sides when you control both;
across organizations, the wire is the protocol: any two implementations of
draft 0.4 and Operations v2 are meant to interoperate, and the conformance
runner (`pap conformance run`) checks a company against it.

## Agent Runtimes

[Agent Runtimes](https://github.com/datalayer/agent-runtimes) 1.3.111 and
later carry the PAP capability (connections, the company role, and the sign-in
display) on `personal-agent-protocol[ui]` 0.7 or later, below 1. The PAP
repository builds every Agent Runtimes PAP example application with the
latest Agent Runtimes release in CI.
