# Migration

What to change when you upgrade across a release that breaks the API. The SDKs
keep no compatibility shims: an old shape is refused, not translated. Each
section names the release that introduced the change; the
[changelog](https://github.com/datalayer/personal-agent-protocol/blob/main/CHANGELOG.md)
has the full list.

## 0.27 → 0.28

0.28.0 implements [PAP draft 0.3](https://personalagentprotocol.org/docs/0.3/spec)
as upstream rewrote it at commit `3e9bada` (revision 2026-10-28). The draft keeps
the number 0.3, but a 0.27 personal agent and a 0.28 company cannot work together:
upgrade both. Python spells the names below in `snake_case`, TypeScript in
`camelCase`; the table after this one lists the TypeScript names that differ by
more than that.

| Change | What to do |
| --- | --- |
| Sessions are local: a random `sid`, no network call | `SessionClient.start(...)` returns a `PapSession`; `renew`, `session_key`, `SessionToken` and the JWT bearer grant are gone |
| Every company request carries `Poppy-Session` | Contribute `pap.sessionSigner` in place of `pap.dpopProofProvider`, or use the default with a `DelegatedKeyCustody` in place of `SessionKeyCustody` |
| Delegations come from the signer | `pap.signer` receives `purpose="delegation"`; its key signs client assertions and delegations only |
| Blind signing is available | `BlindJoseSigner` signs both client assertions and delegations; see [what it gives up](/guides/cryptography/#blind-signing-and-what-it-gives-up) |
| Access and refresh tokens under OAuth's names | Read `TokenResponse`; `AccountTokenClient` is `RefreshTokenClient`; `refresh_token_expires_in` is gone; account clients take an access token, not a Session Token |
| `account_mismatch` is gone | Handle `invalid_session` for an access token of another account in a Session (a company MAY refuse it); start a new Session for a second account |
| DPoP is the company's choice | The SDKs send no proofs and refuse a `DPoP` token response with `unsupported_token_type`; a company's `dpop_signing_alg_values_supported` is its own to list, and ignored ([DPoP](/guides/cryptography/#dpop)) |
| MCP tokens | `token_for_mcp` requests by `resource`; Token Exchange is gone |
| The issuer comes from the domain | A company serves `/.well-known/oauth-protected-resource` with `resource` = `https://{domain}` |
| `invalid_session` is back, `invalid_grant` no longer ends a Session | Handle `invalid_session` by starting one new Session, then stop |
| Rate limits have no body | Read `Retry-After` on the 429; custom `pap.company.rateLimit` contributions return no `rate_limited` body |
| Browser join | `BrowserJoin.submit_join_form()` takes no proof; companies serve `{browser_session_endpoint}/authorize` |
| Mediated Sign-In is an extension grant | Publish `extensions["mediated-sign-in"]`, list the grant type; `auth.mediated` is refused |
| Operations version 2 | `OperationsClient.ask_user` and `send` replace `confirm` and `cancel`; `operations_negotiated` replaces `operations_endpoint`; `cancel_open_operations` is `settle_open_operations`; standing permissions and `PapOutcome` are gone; `pap operations confirm` and `cancel` are `pap operations send` |
| Feedback | `FeedbackReport` has no `kind` |

| What a company's API sees | `ApiCall.carries_approval` says the request came with an approval; `ApiError.body` keeps an `action_failed` body, so a host needs no subclass for the company's words |

In TypeScript, these differ by more than the case of their letters:

| 0.27 | 0.28 |
| --- | --- |
| `DpopFetchClient` | `SessionFetchClient` |
| `AccountTokenClient` | `RefreshTokenClient` |
| `JoseDpopProofProvider`, `DpopProofProviders` | `DelegatedSessionSigner`, `SessionSigners` |
| `InMemorySessionKeys`, `SessionKeyCustody` | `InMemoryDelegatedKeys`, `DelegatedKeyCustody` |
| `offersTokenExchange` | removed |

A custom company store keys Sessions by `client_id` and `sid`, and sees join
codes authorized for a Session rather than proven with its key.

## 0.26 → 0.27

0.27.0 implements [PAP draft 0.3](https://personalagentprotocol.org/docs/0.3/spec)
as of upstream commit `a95b757` (revision 2026-10-26) in place of draft 0.2. A
0.27 personal agent uses only `poppy.json` documents with `protocol_version`
`0.3`, and a 0.27 company publishes `0.3`: upgrade personal agents and the
companies they talk to together. The protocol changes are listed in the
upstream [changelog](https://personalagentprotocol.org/docs/changelog); in the SDKs:

| Change | Python | TypeScript |
| --- | --- | --- |
| Each Session has its own DPoP key, the Session Key; its thumbprint names the Session and `session_id` is gone from every request and response | `SessionToken.session_key` (was `session_id`); `renew(..., session_key=)`, `AccountTokenClient.refresh(..., session_key=None)` (none: a new Session, signed in) | `SessionToken.sessionKey`; `renew({ ..., sessionKey })`, `refresh(ref, { sessionKey })` |
| A DPoP proof provider makes a key per Session | `DpopProofProvider.new_session_key` / `create` / `discard_session_key`; `DpopProofRequest(..., session_key=)` (no `subject=`); `JoseDpopProofProvider(keys)` with a `SessionKeyCustody` such as `InMemorySessionKeys` | `newSessionKey` / `create` / `discardSessionKey`; `DpopProofRequest.sessionKey`; `JoseDpopProofProvider({ keys })` with `InMemorySessionKeys` (a `SessionKeyCustody`); `jwkThumbprint` |
| Resource calls no longer name the User ID: the token's key does | `ApiClient`, `ConversationClient`, `OperationsClient`, `FeedbackClient`, `MediatedSignInClient`, `DpopHttpClient`: no `pairwise_user_id=`; `Who` is `tenant_id` and `issuer` | no `pairwiseUserId` |
| `signed_in` is gone from token responses; the grant says it, and `scope` follows RFC 6749 | `TokenResponse` (wire) and `SessionToken.from_response(...)`; `SessionToken.signed_in` is the SDK's | `TokenResponse`, `parseTokenResponse`, `sessionTokenFromResponse`; `SessionToken.signedIn` |
| `invalid_session` is `invalid_grant`; an ended Session's key is discarded and never used again | `SessionError("invalid_grant")`; `AccountRefreshResult.status == "session_ended"` | the same codes |
| Codes are bound to the Session Key | `DirectSignInClient.begin(..., session_key=)` puts `dpop_jkt` in the URL; `DeviceSignInClient.begin(..., session_key=, protected_resources=)` | `begin({ ..., sessionKey })` (`AuthorizationCodeGrant` removed); `DeviceSignInClient.begin({ ..., protectedResources })` |
| A Bearer token for an MCP server without DPoP comes from Token Exchange; a DPoP one from the Session's own request with `resource` | `SessionClient.token_for_mcp(..., session_key=, subject_token=, resource=)` (no `dpop=`); `renew(..., resource=)` or `AccountTokenClient.refresh(..., resource=)` for a DPoP server; `AccountTokenClient.token_for_mcp` removed | `tokenForMcp({ ..., sessionKey, subjectToken, resource })`; `AccountTokenClient.tokenForMcp`, `SessionGrant`, `parseSessionToken`, `tokenTypes` removed |
| `sign_in_required` is `insufficient_scope`, naming the scopes in `scope`; the `authorization` event always has `scope` | `ApiResult.insufficient_scope(scope)`, `ToolResult.insufficient_scope(scope)`, `Reply(authorization=("insufficient_scope", scope))` | `ApiResults.insufficientScope(scope)`, `ToolResults.insufficientScope(scope)`, `Reply.authorization` = `["insufficient_scope", scope]` (`signInRequired` removed) |
| The issuer's metadata says the sign-in types and scopes: `grant_types_supported`, `scopes_supported`; `protected_resources` replaces `poppy_domains`; `auth.direct` and `auth.device` are gone, `auth.scopes` replaces `auth.custom_scopes`; `auth.scope_hints` | `OAuthServerMetadata.offers_direct` / `offers_device` / `offers_token_exchange` / `lists_resource`; `AuthCapabilities.scopes` / `scope_hints`; `CompanyConfig(scope_descriptions=, scope_hints=)` (no `custom_scopes`) | `offersDirect(metadata)`, `offersDevice(metadata)`, `offersTokenExchange(metadata)`, `listsResource(metadata, domain)`; the field `protected_resources`; `CompanyConfig.scopeDescriptions`, `scopeHints` (`[changes, personalData]`) |
| Discovery redirects must end at `/.well-known/poppy.json` with no query | `DiscoveryError("invalid_discovery_location")` | the same code |
| The browser joins a Session through a form with a one-time code, proven with the Session Key; the browser assertion is gone | `BrowserSessionClient.join(browser_session_endpoint=, tenant_id=, issuer=, session_key=)`; contribution `BROWSER_JOINS` / `BrowserJoin.load_join_form` and `submit_join_form` (was `BROWSER_FORM_POSTS`); `build_browser_assertion_claims` and `verify_browser_assertion` removed | `BrowserSessionClient.join({ browserSessionEndpoint, tenantId, issuer, sessionKey })` returning `{ endpoint, joinedAt }`; `BrowserJoins`, `loadJoinForm`, `submitJoinForm` (was `BrowserFormPosts`); `buildBrowserAssertionClaims`, `verifyBrowserAssertion`, `BROWSER_ASSERTION_TYPE` removed |
| `author` replaces `sender` | `Message(author=Author(type="agent"))`; `staff_reply(..., author_id=, author_name=, author_image=)`; `PapReplies` version 3 (`author`, `name`) | `author: { type }`; `staffReply(id, { authorId, authorName, authorImage })`; `PapReplies` version 3 |
| New: Agent IDs, excluded tasks, alternatives, feedback answered with one, loopback redirect URIs | `start(..., agent_id=)`; `DiscoveryClient.excluded_tasks(company)`; `Alternative.usable_references`; `FeedbackClient.report` returns an `Alternative` or `None`; `CompanyConfig(excluded_tasks=, feedback_answers=)` | `agentId`; `excludedTasks(company, options)`; `usableReferences(alternative, document)`; `FeedbackClient.report` returns an `Alternative` or `undefined`; `CompanyConfig.excludedTasks`, `feedbackAnswers`, `endedSessionMemorySeconds` |

A custom company store sees a new record kind (`join_code`), `StoredSession`
keyed by the Session Key with `ends_at`, `IssuedSession.agent_id`, and codes
that carry `dpop_jkt`. Companies list scopes the protocol does not define: the
reference companies use `orders:read`, `orders:write` and the like, never
`poppy:read`.

## 0.24 → 0.25

0.25.0 implements [PAP draft 0.2](https://personalagentprotocol.org/docs/0.2/spec)
(upstream revision 2026-10-18) in place of draft 0.1. Before 1.0 each
`major.minor` version can break the one before, so a 0.25 personal agent uses
only `poppy.json` documents with `protocol_version` `0.2`, and a 0.25 company
publishes `0.2`. Upgrade personal agents and the companies they talk to
together. The protocol changes are listed in the upstream
[changelog](https://personalagentprotocol.org/docs/changelog#v0-2); in the SDKs:

| Change | Python | TypeScript |
| --- | --- | --- |
| A Bearer-only MCP token request is gone: every MCP server gets a token for its `url`, DPoP when its protected resource metadata lists `dpop_signing_alg_values_supported`, Bearer otherwise | `bearer_for_mcp` → `token_for_mcp(..., resource=, dpop=)`, with `fetch_mcp_server_metadata(...).supports_dpop`; `McpClient(..., reactor=, who=)` | `bearerForMcp` → `tokenForMcp({ ..., resource, dpop })`, `fetchMcpServerMetadata(url, { issuer })`, `McpClient({ ..., reactor, who })` |
| Assertions name the company's `auth.issuer` in `aud` and live at most five minutes | `build_session_assertion_claims(..., issuer=)` (no `token_endpoint=`); new `build_client_assertion_claims` | `buildSessionAssertionClaims({ ..., issuer })`; new `buildClientAssertionClaims` |
| A device link is shown only on the issuer's host or one of its `poppy_domains` (or a subdomain), with the company's name and domain | `DeviceSignInClient.begin(..., organization=, poppy_domains=)` (required); `DeviceSignInStart.organization_name` / `organization_domain`; refusal `unsafe_verification_uri` | `begin({ ..., organization, poppyDomains })`; `organizationName` / `organizationDomain` |
| Mediated Sign-In asks for credentials with the company's issuer, name and domain | `ProtectedInputRequest(..., issuer, ...)` | `ProtectedInputRequest.issuer` |
| The sign-in display names the company | `PapSignIn.organization_name` / `organization_domain`, required for `device` and `mediated` | — |
| No redirect is followed outside discovery | `DpopHttpClient` loses `max_redirects`; a redirect raises `TransportError("redirect_refused")` | `DpopFetchClientOptions.maxRedirects` removed |
| `organization.domain` is the host that served the document after redirects, compared ignoring case only; issuers are compared exactly (no trailing-slash or `www.` normalisation) | `DiscoveryError` | `DiscoveryError` |
| A company's assertion check takes one audience, its issuer | `verify_assertion(audience: str)` | `verifyAssertion({ audience })` |
| New: feedback (section 8) | `FeedbackClient.report`, `FeedbackReport`; `CompanyConfig.feedback`, `CompanyService.feedback_reports()` | `FeedbackClient.report`, `FeedbackReport`; `feedback`, `feedbackReports()` |
| Reference company: DPoP at its MCP server by default, nonces on demand, a device page on its own domain | `CompanyConfig.mcp_dpop=True`, `dpop_nonce`; `device_page` must be on the company's domain or a subdomain | `mcpDpop`, `dpopNonce` |

A custom company store sees two new record kinds (`feedback`, `dpop_nonce`)
and `StoredSession.account_id` (the account a Session was ever signed in to).

## 0.9 → 0.10

A security review of both SDKs changed these contracts:

- **`AccountDirectory.authenticate(credentials, context)`** takes a
  `SignInContext` (`client_id`, `session_id`; `clientId`, `sessionId` in
  TypeScript). The company limits Mediated Sign-In attempts itself; a
  directory must also throttle its own checks.
- **`CompanyConfig` with `operations` needs `write_scopes`** (among `scopes`):
  without one it raises. Set `operations=False` for a company without
  Operations. An operation records the scopes confirming it requires
  (`ProposedOperation.scopes`, else `write_scopes`).
- **`Turn.supports_operations`** (`supportsOperations`) says whether the
  agent negotiated Operations; a company agent must not promise an operation
  to one that did not.
- **The default `pap.company.replayCache` is `StoreReplayCache`** (id
  `store`), in the company store. A contributed store must accept the
  `replay` and `sign_in_attempts` kinds (`check_store` / `checkStore` checks
  them). `createCompanyDefaultsPlugin` and `CompanyDefaultsPlugin` take the
  store to use.
- **Stored records changed:** operations keep `scopes`, Mediated sign-ins
  `attempt_keys`. Records written by 0.9 are refused, not translated: drain
  pending sign-ins and proposals before upgrading.
- **The web cookie is `__Host-poppy_session`.** Browsers holding the old
  `poppy_session` open the page again from the agent.
- **TypeScript `./server`:** `isPublicIpAddress` is `isGlobalAddress`;
  `createResolvingFetch` is the Node company's default `fetch`.
- **Assertions** live at most 120 seconds and carry a `jti` of at least 16
  characters (DPoP proofs too); their `aud` may be the issuer, the token
  endpoint, or the endpoint called.
- **Conversations** frame each agent reply with `working` and `idle` state
  events: read the last message or `authorization` event, not the last event.
- **An operation past `proposed`** has no `expires_at` member (never `null`).
- **`pap operations approve`** takes the user's answer at a terminal or from
  the host's `pap.approvalSurface`, never piped input; approvals stored by 0.9
  are refused at `confirm`: approve again.

## 0.8 → 0.9

- **Removed contribution points that nothing used.** `pap.protocolProfile`
  (`PROTOCOL_PROFILES`, `ProtocolProfile` / `ProtocolProfiles`),
  `pap.extensionHandler` (`EXTENSION_HANDLERS` / `ExtensionHandlers`,
  `ExtensionHandler`), and `pap.keyStore` (`KEY_STORES` / `KeyStores`,
  `KeyStore`, `KeyReference`) are gone: no SDK code ever read them. Read the
  draft the SDK implements from `PROTOCOL_PROFILE`, `PROTOCOL_REVISION` and
  `OPERATIONS_VERSION`; negotiate extensions with `negotiate_extensions` /
  `negotiateExtensions`; keep keys behind your `pap.signer` and
  `pap.dpopProofProvider`. A host that contributed to a removed point
  contributes nothing in its place.
- **Optional points fail closed on ambiguity.** The cache, clock, random
  source, retry policy and rate-limit budget where the SDK can do without
  them, and the company's `pap.company.api` and `pap.company.mcp`, now refuse
  two contributions at the same winning order (`ambiguous … contributions`),
  as every other point does. Give your replacement a lower `order` than the
  default (100). `optional_contribution` / `optionalContribution` resolve such
  a point.
- **Operation executors replace by order.** For one action, the
  lowest-order `pap.company.operationExecutor` performs it; two at that order
  leave the operation `in_progress`. Before, any second executor for an action
  did.
- **TypeScript company: Bearer tokens and MCP.** The TypeScript reference
  company now serves `pap.company.mcp` (`CompanyMcps`, `CompanyMcp`,
  `ToolResult`, `ToolResults`) at `/mcp` with Bearer Session Tokens, as the
  Python one does. `IssuedSession` records carry `tokenType` (`Bearer`, absent
  for DPoP), and a Session keeps its DPoP and Bearer tokens side by side.
- **TypeScript company: renewal with the assertion is signed out.** A Session
  renewed with the Session assertion gets a signed-out token, as in Python and
  §4.2; a signed-in Session is renewed with its Account Token.

## 0.7 → 0.8

- `MemoryReplayCache` takes the company's clock and forgets expired
  identifiers; the verifiers now remember a DPoP proof until its `iat` leaves
  the acceptance window and an assertion until `exp` plus the 30-second skew.
  A replay cache of your own must keep identifiers at least as long as the
  `expires_at` it is given. `check_replay_cache` / `checkReplayCache` check it.
- `SharedRateLimitBudget` refuses a turn beyond `max_wait` at once with
  `rate_limited` instead of queueing past it.
- The built-in consent page binds the browser: read the user's decision with
  `CompanyService.consent_decision(request)` (`consentDecision`), which
  accepts only a same-origin POST carrying the page's cookie and token.

## 0.6 → 0.7

Nothing breaks. `personal_agent_protocol.ui.PapSignIn` needs
`datalayer_reactor` 1.1, through the new `ui` extra.

## 0.5 → 0.6

- **The company store is an async keyed store.** `pap.company.store` holds
  versioned JSON records: `get`, `put`, `create` (only if absent), `replace`
  (compare-and-set on a version), `take` (read and delete at once), and
  `delete`, each by kind and key with an optional expiry. The dict-of-records
  `CompanyStore` (Maps in TypeScript) is gone: port a database store to these
  six operations and run `check_store` / `checkStore` against it.
- **Company methods are async.** `approve_device`, `deny_device`,
  `approve_authorization`, `deny_authorization`, `authorization_request`,
  `revise`, `settle`, `forget_events`, and `disconnect` (and their TypeScript
  names) return coroutines or promises: await them. Read an operation as the
  company keeps it with `operation_record` (`operationRecord`); the in-memory
  `CompanyService.extensions` map is gone.

## 0.4 → 0.5

- **Direct Sign-In keeps the Account Token in `pap.tokenStore`.** The
  result's token no longer carries `refresh_token`; read
  `account_token_reference` (`accountTokenReference`) and use it with
  `AccountTokenClient`, as for Device and Mediated Sign-In.
- TypeScript Session, conversation and operation errors carry a 429's
  `Retry-After` as `details.retry_after` (Sessions used `retryAfter`).
